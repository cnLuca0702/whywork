# WhyWork 界面评审：美观性与操作合理性

- 评审日期：2026-10-16
- **状态更新（2026-10-16 晚）：U-01～U-34、U-36（部分）、U-37 已完成修复，验证见文末「七、修复记录」；U-35（日历日程视图）未实施。**
- 评审对象：main 工作区当前构建（R1–R22 完成后，`npm run build` 于 2026-10-16 01:10）
- 证据：`npm run check:ui` 的十个视图亮暗截图、REMIO-R 验收运行中的界面截图、在隔离实例中补拍的有内容状态和 1024×700 最小窗口截图。关键截图已复制到 `docs/ui-review/`。
- 排除项：截图里的 `⟦SCN:…⟧`、`RT-` 前缀名称、“合成音频验证”按钮都来自测试数据或 `--ui-check` 模式，不计入问题。
- 平台：截图在 Linux（Xvfb）上拍摄，字体回退为 DejaVu/Noto，所以字形和 macOS 上不同；布局、层级、交互问题与平台无关。

## 一、总评

| 维度 | 评分 | 结论 |
|---|---|---|
| 视觉基础（色彩、主题、图标） | 7 / 10 | 颜色令牌完整，亮暗主题切换正确，品牌色统一，图标风格一致 |
| 版式与层级 | 5 / 10 | 标题层级混乱，多处重复标题，卡片间距和对齐不统一 |
| 组件一致性 | 4.5 / 10 | 同类操作有三种按钮样式；代码块、输入框、日期控件各有两套 |
| 导航与信息架构 | 5 / 10 | 同一功能有三个入口，选中状态互相不同步 |
| 关键流程（对话、知识库、确认） | 6.5 / 10 | 功能齐全、流程能走通，但输入区拥挤，工具调用直接显示原始 JSON |
| 可见缺陷 | — | 6 个 P0：抽屉被裁切、弹窗被下拉遮挡、笔记中暴露内部注释和绝对路径等 |

总体判断：功能覆盖已经很完整，主题系统也打好了基础，但界面还停留在“工程验证版”的状态。主要问题不是配色，而是**层级和一致性**：控件堆在一起，主次操作分不出来，同一个概念在不同位置用了不同叫法和样式。先修 P0 缺陷，再统一按钮、表单、标题三类基础组件，观感就能明显提升。

## 二、做得好的地方

1. **主题令牌落地扎实**：`--ww-bg / --ww-card / --ww-text / --ww-primary` 覆盖了自定义组件和 Ant Design，暗色模式下几乎没有漏色（`02-chat-dark.png`）。
2. **三栏布局方向正确**：左侧是知识库和会话，中间是对话，右侧是工具面板，工具竖栏放在最右边，符合“对话为主、工具为辅”的定位。
3. **确认卡设计合理**：删除笔记时在对话内弹出卡片，显示笔记标题和“可在保险箱中回滚”，允许和拒绝都很清楚（`09-confirm-card.png`）。
4. **引用闭环完整**：回答带角标，下方列出来源，点击后打开笔记并高亮命中片段（`08-citation-detail.png`）。
5. **空状态有引导**：新对话页有标题、副标题和四个快捷入口；表格和日历的空状态也用了统一的空图标。
6. **Markdown 渲染质量好**：表格、KaTeX 公式、代码高亮、双链都能正确显示（`13-note-detail.png`）。

## 四、改进方案

### 4.1 设计基线（先做，所有页面都受益）

1. **字号层级**只保留 5 档：页面标题 20/600，分组标题 15/600，正文 14/400，辅助文字 12/400，代码 13 等宽。删掉设置页的 24px H1，统一使用这 5 档。
2. **间距**用 4 的倍数：卡片内边距 16，卡片之间 12，同组控件之间 8。把它们写成 `--ww-space-*` 令牌。
3. **按钮层级规则**见 U-26，并关闭两字按钮插入空格（U-27）。
4. **表单**一律使用上方标签加字段下方说明，不再只用占位符当标签（U-28）。
5. **新增代码块令牌**和 `--ww-code-*` 系列，统一对话和笔记里的代码块（U-05）。
6. **浮层层级**：自定义的固定元素（竖栏、状态栏）的 `z-index` 都要低于 Ant Design 浮层的 1000（U-01）。

### 4.2 导航重组

│ ─ 集合 ▾ ─      ││                         ││                     ││ 📅 │
│ ─ 最近对话 ▾ ─  ││ [输入框 + 统一工具条]    ││                     ││ ✉️ │
